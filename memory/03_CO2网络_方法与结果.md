# CO₂ 加氢网络：方法与结果

详细文档在各目录的 README（`co2_hydrogenation_network/README.md`、`tandem_kinetics/README.md`、`web/README.md`、`deck/README.md`）。这里只记要点和决策。

## 1. 全化学空间估计（`scripts/chem_space.py` 等）

- **生成方式**：逐个加重原子（C/O），新原子连到父分子任意一组有空价的原子上，键级 1–3；用 RDKit 规范 SMILES 去重。芳香父分子展开全部凯库勒式。
- **完整性**：每个 n+1 原子分子都有非割点，删掉后得到合法的 n 原子分子，所以不会漏。
- **过滤**：raw 层只去掉小环（< 8 元）内的三键或累积双键，以及 O–O；plausible 层再去掉张力结构。
- **自由基**：在每个不等价的含 H 原子上去掉一个 H。
- **反应族**：复合、加成、β-断裂、开环、H 迁移、四中心消除、CO 脱除、酮–烯醇互变、Diels–Alder，以及 N² 级的 H 抽提、歧化、SH2。
- **规模结论**：反应数被"任意两个自由基之间的 H 转移"主导（∝ N_rad²）。已知产物后，只保留产物骨架 + 小自由基池（H、OH、CH₃…），规模能降 15–20 个数量级。

## 2. 同分异构体分辨的机理网络

- `scripts/isomer_scale.py`：统计。按页面里的物种类别（烷、烯、二烯、环烷、环烯、环二烯、芳烃、碳正离子、自由基 / 吸附烷基、醇、醛、酮、酸）和反应族显式枚举；伯碳正离子不计。设置环境变量 `DUMP=` 时导出图。
- `scripts/network_gen.py`：C16 主力生成器。**每条反应都记录全部参与者**。
  - 输出：`species.tsv.gz`（id、class、C、smiles、skeleton）和 `reactions.tsv.gz`（id、family、reactants、products、equation）。
  - 反应族（25 个）：
    - Z 族（分子筛）：prot、hshift、alkylshift、pcp、beta、meth、cyclise、HT；
    - H:hyd；
    - M 族（金属位）：betaH、CH2、CO、hyd；
    - O 族（含氧化合物）：dehyd、hyd、ox、OH；
    - R 族（自由基）：abs、beta；
    - A 族（芳烃）：meth、iso、FC、cyc、hcp；
    - C1。
  - C1 核心是手写的：CO₂ → 甲酸盐 → 甲醇 → SMS；CO₂ → RWGS → CO* → HCO* → CH₂*；SMS → 芳烃池（HCP）→ 乙烯 / 丙烯。池物种：H₂、H*、H⁺、H₂O、[H]（氢转移受体）、H•。
  - `--full-upto 12`：C13 以上只保留 ZSM-5 可以容纳的骨架（只允许甲基支链、≤ 2 个支链点、无季碳；环体系 ≤ 2 个直链取代基）。
  - 补的三类反应：侧链脱氢环化（茚满、四氢萘）、稠环饱和环脱氢（四氢萘 → 萘类）、R* + OH* → 醇。补完后推荐版只剩 160 个不可达物种（158 个是择形排除了前体，2 个是四甲基环己烷），全量版只有 17 个。
- **规模**：
  - 推荐版 128 390 / 367 369；
  - 全量 C16 4 776 003 / 15 500 138，用 4 核约 68 分钟、约 6 GB 内存；
  - 全量反应构成：质子化 385 万、PCP 180 万、HT 155 万、1,2-H 154 万、烷基迁移 134 万、SMS 甲基化 128 万、β 98 万……
  - 双分子负氢转移按离子对计 2.5×10¹²，只计数。

## 3. 路径搜索的定义（网页里用的，Python 和 JS 两种实现结果一致）

- 每条可逆反应拆成正、逆两条有向超边；`A:hcp`（多甲基苯 → 烃池）只允许正向。
- 起点：CO₂ 加池物种。按层做 BFS：一条反应的所有输入都可达后，输出的层数 = 输入层数最大值 + 1。
- 最短路径：每一步只跟随含碳的"主输入"（层数恰好为 L − 1 的非池物种），用 DP 计数。服务器端预先存每个物种最多 12 个"紧父节点"，网页只沿路径懒加载数据块。
- 例子：对二甲苯 17 步、70 条最短路径；正十六烷 19 步（推荐版 56 条，全量 76 条）。

## 4. 网页（`web/`）

- `index.html`：推荐版，WebGL 一次画全部点和边；使用 `nodes.json` + `reactions.json`。功能：搜索、筛选、全部反应列表、路径搜索加画布高亮。`build_offline.py` 生成单文件离线版。
- `lod.html`：全量分级加载。数据块由 `lod_build.py` 生成：l（标签、层数、路径数、父节点）和 x（每个物种的反应记录，用 zigzag varint 编码差值），gzip 后再 base64 包成 `.js`。层级：① 格子 + 格间流量；② 推算点位；③ 加载标签；④ 加载反应。
  - 布局：物种数 < 10⁶ 时用 sqrt 缩放，否则用立方根缩放，并给 padding 设上限。全量版因此重建过一次 meta。
  - `lod_package.py` 打包离线版。
- 两个在线 Artifact 链接见 `00_项目总览.md`。

## 5. PPT（`deck/`）

- 用 pptxgenjs 3.12.0 的原生形状绘制。节点类型：分子、引用副本、表面物种、自由基、离子。反应边分 R1–R6、SH 几类。用大色块表示催化剂类别（OX、CU、MET、CARB、DUAL、SUP、BA、LA、BIF、EC、GAS）。
- 字体 Noto Sans SC。脚本在 `deck/`，生成方法见 `deck/README.md`。需要先在 `deck/` 下 `npm install`。

## 6. 两条航煤路线对比（`scripts/route_compare.py`、`route_figure.py`）

- 路线 A（DRM → 合成气 → 费托 → 加氢提质）从 CO* 进入，不允许甲醇相关的族：C1 里的甲酸盐、甲醇、SMS、DME、HCP、RWGS，以及 Z:meth、A:meth、A:hcp。
- 路线 B（CO₂ 直接加氢）从 CO₂ 进入，允许全部族。
- 结果：

  | 网络 | 物种共享 | B 独有物种 | 反应共享 |
  |---|---|---|---|
  | 全量 | 4 775 971 / 4 775 980 | 9 个，全是 C1 入口 | 91.6% |
  | 推荐版 | 99.92% | 107 个（9 个 C1 + 98 个只能由甲基化得到的多甲基茚满 / 四氢萘） | 92.2% |

- 图：`figures/route_shared_network.png/pdf`。左侧是两条工艺链，中间是网络（蓝色 = 共用，橙色 = 只有 B 使用），下方三块统计面板。字体在 `assets/fonts/`。

## 7. 串联动力学模型（`tandem_kinetics/`）

- 模型：72 个集总物种、296 个反应；氧化物用 LHHW + Bussche–Froment 平衡；用 BDF 解平推流（PFR）。
- 校准：只用文献，三个体系：
  - G1：郭组 GaZrOx/Ga-ZSM-5，Adv. Sci. 2026；
  - G2：ZnO/ZrO₂–ZSM-5，J. CO₂ Util. 2019；
  - B1：In₂O₃/HZSM-5，Nat. Chem. 2017。
- 分析：DRC 敏感度、32 组随机先验的可辨识性、氢平衡给出的芳烃上限、Z7b 脱氢芳构化。结论见 `00_项目总览.md`。

## 8. 文献调研（`reports/`、`research_notes/`）

- 证据只到摘要级，碳基准普遍无法核实。
- Fe 基 CO₂-FTS 与 OX-ZEO 的产物分布表；含氧化合物以甲醇为主；航煤方向只有新闻，没有数据。
- 机理：甲醇（DME）是氧化物和分子筛之间的中间体。

## 9. 物种级数据库（2026-11-05）：一个物种一个节点，不含离子、不含伪物种

- 起因：用户说想要的是"热催化反应网络"，不要带离子的结构。我解释了分子筛里的碳正离子其实是 R⁺···Z⁻ 离子对或 R–O–Z 烷氧基，电荷是平衡的，网络里的 R⁺ 只是简写。用户随后问"只考虑物种是不是可以和自由基合并"，然后要求"只考虑物种，做一个最完整的数据库，一个物种只有一个节点"，接着又要求"那些伪物种给我去掉"。
- `scripts/species_merge.py`：输入 net_C16_full 或 net_C16_shape，输出 `data/net_C16_species/`（全量）和 `data/net_C16_shape_species/`（推荐版）。合并规则：
  - R⁺（酸位）、R*（金属位）、R•（气相）同骨架同位点 → 一个中性开壳层 SMILES 节点；
  - 烯丙基等共振写法 → 一个节点，代表写法取字典序最小；
  - H⁺ / H* / H• → H；CO₂^δ−* → CO₂；H₂CO* → 甲醛；SMS → [CH3]；
  - `aliases.tsv.gz` 记录旧物种到节点的对应。
- 修正生成器的三处简写：M:CO 漏一个 H → 加酰基节点 + M:acylH；H₂COO + H → H₂CO + H₂O 漏 H → 经过 H₂COOH；H₂ → H 改为 H₂ ⇌ 2H。
- 伪物种：Z:HT 里的 [H] 改成 "→ 产物 + n H₂"（n = 1 或 2）；烃池 HCP 的 14 条集总反应删掉，改为显式的侧链甲基化 A:scm（22 603 条），并保留已有的 A:meth 和 A:FC。
- 反应每边最多 3 个物种；同一方程（正反向视为同一条）合并成一行，`families` 列出所有机理族。
- 结果：
  - 全量：4 347 082 个节点，15 257 371 条反应，0 条元素不守恒；从 CO₂ + H₂ 出发只有 17 个不可达（带季碳的多甲基环己烷），最远 22 步；
  - 推荐版：114 187 / 359 149，81 个不可达（择形导致）；
  - 4 核约 19 分钟。第一版把 1 500 万行一次性 tolist，内存溢出被杀，改成分块后峰值约 8 GB。
- 查询：`scripts/species_query.py`（DuckDB，支持 --node / --reactions-of / --old / SQL / --export）。

## 10. 子网络提取（`scripts/subnet_extract.py`，2026-11-05）

- 用户需求："规定反应物、生成物和比最少步数大几步的范围，把中间的反应网络单独提取出来，可以导出"。
- 判据：
  - 前向：最早步数 f，按层算，和网页一致；
  - 反向：关键路径的最晚时间 L（经过每一步的所有输入）；
  - 收录：一个反应步满足 f(e) ≤ T(e) 就收；
  - 额外步数：每步最少需要多大的 k 才会被收录；
  - 消耗目标的反应步不收。
- 第一版用"到目标的最少步数 b"，没有考虑共反应物的时间，下界太松，k = 0 时有 13 万个反应步，还出现负余量。已经弃用。
- 重要现象：k ≥ 1 时规模爆炸（推荐版 CO₂ → 对二甲苯：167 → 262 038 → 401 415），原因是齐聚一步碳数翻倍，"先长大再裂解"的路线都赶得上。用 `--max-c 8` 时为 167 / 5 581 / 6 419。
- 导出：网页.html（自带 smiles-drawer、按步分列、按额外步数筛选）、物种.csv、反应.csv、subnet.json、subnet.graphml、说明.txt。第一次读全量库约 2 分钟，之后用 `_cache.pkl`（gitignore）；全量不加碳数上限时每个目标约 20 秒，另加约 70 秒准备。
- 交付：`downloads/物种级数据库_分卷/`（7 个 `.zip.0NN` 分卷，gitignore）+ 示例网页。

## 11. 物种级网页（2026-11-05）

- 用户要求："网页版有上面所有的功能，可以查看全量反应"。
- `web/lod_build_species.py`：从物种级数据库生成分级加载数据块，格式沿用 lod_build。扩展了两处：
  - l 块的类别字节里，低 5 位是类别，高 3 位是位点掩码（1 = 酸位，2 = 金属位，4 = 气相）；
  - x 块每边最多 3 个物种。

  行（类别）：醇 / 醚、醛 / 酰基 / 酮 / 羧酸、R 基团·烷基、烷烃、烯烃、R 基团·烯基、二烯、环烷 / 环烯、R 基团·环状、环二烯、芳烃。反应族组合共 30 种（≤ 32）。全量构建约 5 分钟，标签 44 MB + 反应 112 MB（压缩后），共 109 块。
- `web/species_index.html`：以 ec_space 的通用模板为基础。
  - 新增：位点标签、"设为起点 / 加为终点"按钮、左侧"子网络提取"面板。
  - 提取在浏览器里完成：下载全部 x 块后建图，同一条反应只由参与者中编号最小的非池物种保留一次；算法与 subnet_extract.py 相同。
  - 结果在页面内用 iframe srcdoc 浮层显示（弹窗在 Artifact 里不可靠）；导出用 `claude.use("downloads").save()`，离线时退回 `<a download>`。
- 验证：网页提取与 Python 完全一致。
  - 推荐版：CO₂ → 对二甲苯，C ≤ 8，k = 0/1/2：167 / 5 581 / 6 419，耗时 0.3 秒；
  - 全量：同一结果，首次 11 秒（含下载解析），不限碳数时计算 6.4 秒。
- 离线版：`downloads/物种级网页_离线版/`（推荐版单个 zip 3.6 MB；全量 4 个 `.zip.0NN` 分卷，155 MB；gitignore）。
- 重建：`python lod_build_species.py ../data/net_C16_species 输出目录`，标题会按版本自动写入。
