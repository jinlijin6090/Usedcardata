# EC 化学空间硬枚举（`ec_space/`）

用户要在自己的服务器上硬枚举 EC（O=C1OCCO1）分解和自反应的整个化学空间：最多两个 EC 的重原子数（12 个），包含全部自由基和离子。只去掉"极其不科学"的结构。要求多核、数据库形式、网页预览，全部依赖打包好，改提交文件的一句话就能运行。

## 规模结论（之前讨论过的）

| 范围 | 闭壳层分子 | 含自由基 / 离子 |
|---|---|---|
| 原子只来自 ≤ 2 个 EC（C ≤ 6、O ≤ 6、H ≤ 8），精确 | 2 671 907 | 单自由基 11 279 481 |
| 开放 C/H/O、≤ 12 个重原子（产物可以继续反应，H 可以在多个 EC 之间转移） | 精确到 9：964 497（无过氧）；外推 ≤ 12 约 1×10⁹ | 单位点约 2×10¹⁰；按程序默认的完整定义（加上双位点和 Li）约 1.7×10¹¹ |

文献对比：
- Blau 2021（Chem. Sci.）约 6 000 个物种、450 万条反应；
- Spotte-Smith 2022（ACS Energy Lett.）> 5 000 个物种、> 8 000 万条反应；
- HiPRGen 2023（Digital Discovery）约 5 200 个物种、8 600 万条反应。

这些网络都是人工筛选过的 DFT 物种，不是穷举。

## 生成逻辑

1. **闭壳层分子**：与 CO₂ 网络同一个算法（逐个加原子；非割点论证保证不漏；凯库勒式；对称剪枝）。
   - 过滤：去掉 < 8 元环里的三键或累积双键，去掉 O–O–O 链；单个 O–O 默认保留（`allow_peroxide`）；可选 plausible 张力过滤。
   - 特殊物种：CO（`[C-]#[O+]`）。
   - **规范 SMILES 要往返校验**（`stable_smiles`）：RDKit 2025.03 会给同一个应变稠环分子两种写法。
2. **磁盘分片去重**：
   1. 各进程把子分子按 crc32 写进各自的分片 gzip，追加写入；
   2. 每个分片单独读入 set 去重并排序；
   3. 每层写 `DONE.json`，用于断点续跑；
   4. 分片数自动取"每片约 200 万个"。
3. **派生物种**（每个母体内部去重；把 H 或电子放回原处可唯一还原母体，所以不需要全局去重）：
   - 单位点：rad、an、cat（默认只有 C）、prot（O）；
   - 自由基离子：`母体|±1`，不定域；
   - 双位点：`pairs`，默认 distonic（自由基 + 负离子，负离子在 C 或 O）和 dianion（只在 O）；可选 biradical、zwitterion、radical_cation_pair；
   - Li⁺：O→Li⁺ 用 RDKit 的 DATIVE 键表示，最多 `li_max` 个；
   - 只保留电荷在 `charges` 范围内的物种。
4. **反应**（14 族，每条只由一方负责生成）：
   - 派生物种负责和母体之间的连接步（加减 H•、H⁺、H⁻、e⁻、Li⁺）；
   - 母体负责均裂、异裂、自由基阴 / 阳离子断键（环上的键断开即开环，例如 EC•⁻ → `[CH2]COC(=O)[O-]`）；
   - 单自由基中心的物种负责 β-断裂；
   - 双位点物种负责 `pair_steps`；
   - `allowed()` 检查产物是否属于当前配置的物种类别，不属于就不写这条反应；
   - 不枚举任意两个大物种之间的双分子反应（约 10²⁰ 条）。
5. **超过 `derive_max_heavy` 的层**：按 crc32 哈希做确定性抽样（`count_sample`），只计数。
6. **网页**（`viewer.py`）：
   - 行 = 8 类物种，列 = 重原子数；
   - 从 EC 出发，池物种为 e⁻、Li⁺、H•、H⁺、H⁻；
   - 页面由 CO₂ 的 `lod.html` 改造：类别名、颜色、族名、起点、默认选中都由 meta 提供。

## 已知的 RDKit 陷阱

- 带 dative 键的 `[Li+]` 被重新解析时，RDKit 会给 Li 记 7 个幽灵自由基电子。计算多重度时要忽略 Li（`info_of`、`centres` 里已处理）。
- 规范 SMILES 不稳定，用 `stable_smiles` 往返校验。

## 验证（都在 `tests/selftest.sh` 或手动跑过）

- 关掉过氧键时，闭壳层分子数逐层为 2、5、17、77、379、2 270、15 196、115 323、964 497，与独立实现一致。第 8 层独立实现是 115 325，多出的 2 个是同一分子的两种写法。
- EC•⁻ 开环反应存在；EC + e⁻ → EC•⁻ → •CH₂CH₂OCO₂⁻ 是 2 步。
- 在干净环境（`env -i`）里，用全新目录、分卷环境包做过完整流程和断点续跑测试。
- 设置 `EC_MP_START=spawn` 时结果与 fork 完全一致（Windows / macOS 用 spawn）。

## 性能标定（4 核测试）

- 每个母体：派生物种 52、70、89 个（重原子 6、7、8）；反应 100、137、186 条；派生 CPU 约 40 ms；生成 CPU 约 12–17 ms。
- 压缩后：每个物种约 7.1 B，每条反应约 8.4 B，每个闭壳层分子约 4.5 B。去重前重复约 4.8 倍。
- 默认配置估算：约 1 400 核时（64 核约 22 小时），写出约 8 GB，临时文件峰值约 26 GB，每核约 2 GB 内存。
- 估算器 `estimate` 阶段：先精确算前 7 层再外推；用重原子 8 实测核对，只低了 3%。

## 打包

- 环境：micromamba（从 conda-forge 拿到；micro.mamba.pm 和 api.anaconda.org 在当时的沙箱里被拦截，但 conda.anaconda.org 可以访问）建 python 3.11 + numpy + python-duckdb + conda-pack，RDKit 用 pip 装 2026.9.1。conda-pack 打包后 165 MB，拆成 4 个分卷。
- `run.sh`：自动合并分卷、解压、执行 conda-unpack，然后运行，日志用 tee 写到配置文件所在目录。
- `run.py`：在任意已安装好依赖的 Python 上运行（Windows / macOS）。
- 用户只需要在提交文件里写：`bash /path/ec_space/run.sh /path/ec_space/config.ini`。
