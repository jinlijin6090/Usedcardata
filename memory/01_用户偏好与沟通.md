# 用户偏好与沟通

## 用户

- 名字 Jin，研究方向是 CO₂ 加氢（多相催化、航煤），也关心锂电电解液反应网络。
- 本地电脑是 Windows（下载路径出现过 `C:\Users\Jin\Downloads\CRN\`）。另有可以提交作业的服务器（有自己的提交文件，可能是 SLURM 或 PBS）。
- 计划让另一个 agent 在本地安装和运行环境。

## 沟通方式

- 全部用中文。用户的消息通常很短、口语化，一句话里可能有好几个要求，要逐条拆开理解。
- 用户会追问"为什么"和"逻辑是什么"，比如为什么同时有碳正离子和自由基、生成逻辑是什么。回答要讲原理，并配上例子（具体分子、具体反应）。
- 歧义大、而且会改变工作量时，用选项式提问（列出推荐项）。用户会直接选，或者用一句话改写需求。
- 用户有时一次回答好几个问题，或在回答里追加新需求。比如问 C16 时，选了推荐方案，同时要求全量统计、多级加载网页、反应列表和路径搜索。

## 交付偏好

- **要"成品"**：单页 PPT（可以很大、可以凌乱，但要完整）、交互网页（缩放、搜索、点物种看全部反应、路径）、离线包（双击就能打开）、一键运行脚本（"改提交文件里的一句话"）。
- **要"硬枚举""全部列出"**：不要擅自缩小范围。做不到时，给出精确规模和资源估算，再提供裁剪方案让用户选。
- **图要设计过**：例如用户说"截图就行，但你帮我好好设计一下"，最后做的是用网络数据重新渲染的出版级图，配色、版式和统计面板都经过设计。
- **打包要全**：依赖、环境、说明、自检都要放进去，在用户那边一次就能跑通。

## 踩过的坑

- **大文件发不过去**：171 MB 的 zip 发送显示成功，但用户看不到。之后一律拆成 ≤ 45 MB 的分卷：每卷是独立可解压的 zip，并附"先看我"说明；同时放一份到 GitHub 分支作为备用。
- **"另一个程序正在使用此文件"**：这是 Windows 的提示，原因多半是下载未完成或杀毒软件在扫描。给用户每个分卷的精确字节数，让他核对。
- **在线页面的格式限制**：claude.ai Artifact 不托管 `.bin` 文件，数据块要改成 `.js`（base64 包装，用 `<script>` 加载），这样本地 `file://` 打开也能用。
- **对外链接是私有的**：每次都要提醒用户在 Share 菜单里共享，别人才能打开。
